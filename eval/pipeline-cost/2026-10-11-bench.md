# The bakery bench: main against the cheaper-videos branch (2026-10-11)

The README's bakery request, measured as it ran (the pipeline-cost skill's bench, `.claude/skills/pipeline-cost/bench/`),
once on main and twice on the `cost-audit` branch: as first built, and with its `frames` stage fixed after the first
run showed it slow. Each run on a fresh EC2 c7i.4xlarge (Ubuntu 24.04, Node 22, Claude Code 2.1.296), Opus 5.5 at
medium effort for every request (checked per request in the telemetry), headless (`claude -p`, auto mode), with the
person's one answer given in the prompt (the whole pipeline) and the same scripted review every run: the recommended
option of each decision, Request changes, and the baseline's comment that no step gets the bakery a web address.

Times are from reelplanner's own commands (a shim on PATH) and Claude Code's telemetry (each request's exact tokens,
cost and duration), not from transcripts. Phase minutes are agent-minutes; Verify includes rework (building again
because of what fresh eyes found). Cost is what the telemetry prices each request at; on a subscription it is usage,
not a bill.

## What the runs found

- **The first `frames` stage cost more than it saved.** It checked each changed frame three times, counted every
  frame as changed (a build leaves `index.html` untouched when its content is the same, so its time is no measure),
  and stopped on overlaps verify passes and on frame-lint, which no later stage runs: 92 s a build, 7 of 11 builds
  stopped. Fixed: the stage runs verify's own check (13.5 s on a 19-frame video), only when a frame's hash changed
  since the last build that passed, and stops only on what verify would.
- **The fixed run still stopped twice needlessly,** on voice files and a frozen timeline in the last assembly after
  the script had changed. Fixed after this run: the stage is skipped when the storyboard or script changed. This
  run's numbers include those two stops.
- **The other failed builds are fair stops:** a decision id shown alone (check-terms), the script at 7:31 against the
  7:30 limit (the length stage), the guide's check.
- **Plan time is short headless** (2–3 min in every run, against 9 in the interactive baseline): no one to talk to.

## Limits

- One run per side: agent runs vary, and one run cannot say how much of a difference is noise. A second run each
  was planned; main's second was cut off mid-revision and the fixed branch's second was stopped, to save usage.
- Headless with a scripted review, unlike the 2026-10-10 interactive baseline: compare these rows with each other,
  not with that one.
- The scripted review is the same in kind every run, not word for word: decisions differ between plans.
