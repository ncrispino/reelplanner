# The bakery bench at low depth (2026-10-22)

The README's bakery request, three times, on the `depth` branch (#35): the depth feature of #34, then the fixes
each run led to. They were measured as the [2026-10-11 bench](2026-10-11-bench.md) was:
- a fresh EC2 c7i.4xlarge for each run, Claude Code 2.1.309;
- Opus 5.5 at medium effort for every request, checked per request in the telemetry;
- headless, with the same scripted review.

The prompt is the baseline's with one sentence added: "Make it a low-depth video." The agent wrote `depth: low` in
the brief each time. The bench's `--depth low` adds the sentence (`.claude/skills/pipeline-cost/bench/`).

At low, verify runs inside the build (about 25 s a build), and no fresh eyes follow it. The video is shorter by
design: under 2 minutes and 8 scenes, against the baseline's 18. This measures the depth, not the same video made
cheaper.

## The depth held, every run

- At most 8 scenes and under 2:20. The length stage said "a plan video at low depth: aim 1–2 min, at most 8 scenes".
- No fresh eyes: the build's `fresh-eyes` stage said "none at low depth", and no `fresh-eyes` command ran.
- No strict checks: check-terms' findings were warnings.
- The review was taken in each time: the decision recorded, and a step for the web address the review asked for.

## Run 1 (13.2 min): three things avoidable, about 3.8 min

The plan took 2.4 min, and the brief, storyboard and script 2.3. Narration ran in the background while one generator
script drew all 8 frames, about 3 min. The rest was builds and rework.

- **The guide's check failed the first build, and the revision's** (a 65 s build, then the agent's fix). This bug is on
  main too:
  - The guide draws plan.md's "Decisions in force" under its own headings, and leaves out the section's words that
    are no line of it.
  - So `guide --check` failed a first plan's "None yet: this is the first plan.", and a section citing the plan's own
    decision (the revision).
  - The guide spec passed only because its fixture has a line that names no step: the page's warning about that
    line said the heading's words.
  - The agent got past it by deleting the section from plan.md, both times.
  - Fixed on #35: the page shows the section under its own heading, with its words (`lib/guide/model.mjs`,
    `templates/guide/guide.js`). A guide spec check fails without the fix.
- **The script came out at 2:53, 532 words, against low's 2 minutes.** The agent cut it after narrating, narrated 6 of
  8 lines again (69 s), and drew the frames again: about 1.5 min. The skill now says about 330 words before
  narrating.
- **A whole build (64 s) only to vary the transitions** (5 of 7 were push-slide). The skill now says to run
  `reelplanner variety` before the build.

## Run 2 (12.8 min): those three fixed, two new ones

The script came in at 1:50, the guide's check passed, and no build was spent on transitions. But:

- **Two frame workers took 5.2 min and twice the tokens** (16.5 agent-minutes in 11 of wall, $4.92 for the build
  against run 1's $2.19). The skill had said to hand the frames to workers; run 1's one generator script took 3 min.
  The skill now says, at low, to draw them yourself from one set of styles.
- **Two builds stopped on what `frame-check` had passed:**
  - HyperFrames' lint: the workers styled each frame's root by its class. `frame-check` never ran that lint, and its
    layout check dropped lint findings, which name their file by its full path. Fixed: `frame-check` runs it and
    fails the frame on an error. A frame-tools spec check fails without the fix.
  - An overlap in one frame: the layout check needs the video assembled, so a first build is the first to see it.
- **The revision built again for check-terms' warnings** after a build that passed: about 1.6 min. The skill now says
  to run `check-terms` and `variety` before the build.

## Run 3 (10.8 min): no failed build, one avoidable pass of 3.8 min

Plan 1.8 min, brief to script 1.1, narration in the background while one generator script drew the 8 frames (1.6 min),
a first build that passed at 6.4 min. Then:

- **It checked the 8 frames one by one** (2.1 min, 16 s each on this machine, most of it starting a browser), found
  two warnings, fixed them and built again (1.7 min). The warnings: one contrast of 2.95 against WCAG's 3.0, and
  HyperFrames' wish for an id on every element, which is for editing in HyperFrames' Studio and which run 2's fix had
  started showing.
- **The revision did the same after its build:** 5 frames one by one, 1.4 min.

Fixed: `frame-check` checks several frames, or `all`, in one go (one lint, one layout check, one picture call). All 8
take 18 s on a laptop, against about 90 s one by one. It leaves out the Studio warning. At low, the skill now says:
`frame-check all` before the build (the lint that stops it), and after a build that passed, look once and show it;
only what a viewer would misread is built again. With that, the first video would have come in about 7.5 min and the
revision about 4.2. Unmeasured.

## The bench

- The scripted reviewer posted the bare review, not the row the page posts, so `reel-intake` refused it ("names no
  plan directory"). The agent filed it with `reel record` instead. The 2026-10-11 runs posted the same way. Fixed: the
  reviewer posts the page's row (`planDir`, `project`, `review`), and `reel-intake --dry` takes it.
- The results left out the narration (`*.wav`), so a run's video came back silent. They keep it now (a few MB).

## Limits

- Three runs, each on a different commit: each measures its fixes once. Agent runs vary, and one run cannot say how
  much of a difference is noise. Run 2's slower build is mostly the workers, a choice the skill made.
- The baseline is 11 days older and ran every check. Medium, the new default, is not measured yet.
- Quality is judged by the variety count and a look at the frames. They are plain and consistent: wireframes, the
  real `bakery.json`, the form, a quick check with three answers, and much empty space.
