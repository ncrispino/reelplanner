# Walkthrough: Deep dives

**Status:** implemented on branch `claude/clever-knuth-b5gtcf` · **Plan:** `plan.md` · **Decisions taken:** D-021 = a side panel beside the paused video · D-023 = code only when justified · D-024 = fixed page types first, a fresh page when none fits · and the reviewer's rule: a detail must hold what the video cannot

Built by two agents at once against one contract (the pipeline side and the player side), from commit
`b2225ec`. Each logged its own calls as it made them. Together they made 39 (42 with the three the code check found), far past the dozen the
build rules allow before saying the plan left too much open: **it did.** The plan said what a detail is
and where it opens, but not how a page is filled, what the check refuses, or where the plan text goes
when the page is full. The 15 calls below are the ones worth judging; the other 27 are listed after them.

## What was done, per step

### Step 1 — Deep-dive beats ✅ (one deviation)

A beat can carry `- detail: <name>` (with `detail_title`, `detail_kind`, `detail_why`), and
`scripts/plan-map.mjs` lists each detail in `plan-map.json` with its frame, step and title. In the player
(`packages/player/reelplanning-player.js`), an **Open** chip shows on any frame with a detail; opening pauses
and shows the page in a side panel beside the stage (D-021), full-window on a phone and on windows too
narrow to keep the stage usable (A2). Closing plays on from where you were (A4). D-004 holds: a detail sits on a beat and never replaces a pick-all question's summary frame. D-005 holds: opening a detail is not a rewind, and time in the panel is recorded as `watch.details`, not as watching (`packages/player/reelplanning-player.js`). **Deviation:** the key is
**O**, not the plan's E, because E is Export (A1).

### Step 2 — Kinds of detail, most of them things to try ✅

Seven templates in `templates/details/`: explore, try, evidence, table, code, plan-text, and a blank
`fresh.html` for a page none of them fits (D-024, A10). Each is one self-contained file, themed light and
dark, filled by a JSON block (A11), and ships with a worked sample from the uploads plan (A12).
`reelplanning detail new <video> <name> --kind <k>` (`scripts/detail.mjs`) copies one into a video.
Style guide §20 (`skills/plan-to-video/references/style-guide.md`) carries the reviewer's rule and its
test: write the sentence the video would say instead; if it is enough, there is no detail.

### Step 3 — Comments inside a detail ✅

Every template carries a small bridge: click or select an anchored line, row or part and the page tells the
player, which opens "Comment on `row: 16 MB`" in the panel (A9: clicking a control inside the page works the
control instead). The comment is an ordinary note plus `detail: { name, anchor, text }` (A6);
`scripts/resolve-plan.mjs` and `scripts/revise-scope.mjs` place it under its step with where it points.

### Step 4 — Walkthroughs open onto what changed, not always the code ✅

A walkthrough beat for an agent's call can carry a detail, and the panel then offers Accept / Flag for that
call (A7); `scripts/resolve-walkthrough.mjs` lists comments made inside it. The skill
(`skills/plan-to-video/SKILL.md`) says each call opens onto whatever judges it fastest: a before/after, the
evidence behind a value, or code only when the call is about the code (D-023).

### Step 5 — The whole plan as a page beside the video ✅ (one deviation)

`plan-map.json` carries the plan's own text from `plan.md` (A8), and the player shows it, one section per
step, with the step the video is on ruled in coral; clicking a step jumps there. **Deviation:** not below
the player as the plan says: beside the stage when the window is wide, in the record otherwise, because the
record sheet covers whatever sits below the player (A3).

### Step 6 — Every detail works before you see it ✅

`scripts/check-details.mjs` runs in `scripts/finish-project.sh` and `scripts/verify.sh`: a missing page, a
network load, a page without the bridge or with an error stops the build, plus a few more ways an Open chip
could lead to a broken page (A13); without a browser it still runs its static checks and says so (A14).
`scripts/bundle-player.mjs` carries each video's `details/` to the review page. This plan's walkthrough
video is the first real test: it is built with one detail of each kind.

## Code check

Run 2026-09-23 by a fresh agent from `code-check/brief.md` (`b2225ec..HEAD`); findings in
`code-check/findings.md`. Steps 1–5 carried; D-004, D-005, D-021, D-023 and D-024 hold. Each ✗:

- **Step 6**: right. The plan says this plan's own video is rebuilt with one detail of each kind; it
  was not. **Deviation:** the walkthrough video carries them instead. The plan video was reviewed and
  approved twice, so rebuilding it would put a changed video in front of the reviewer with nothing left
  to decide there; the walkthrough is the next video they watch, and each of its calls opens onto a real
  detail, which is the test the step asks for.
- **`packages/player/reelplanning-player.js:2579`**: the contract between the two halves named
  `watch.details` and its shape, but the plan does not, so it needed a row: m25.
- **`packages/player/reelplanning-player.js:870`**: a real, unlogged call: m26.
- **`packages/player/reelplanning-player.js:1198`**: right, and a bug, not just a missing row: opened
  from the plan text, a comment's frame and step disagreed. Fixed after the check (m27): the comment's
  moment is the detail's own beat when it was opened away from it; a new check in
  `packages/player/test/details.spec.mjs` covers it.
- **`scripts/check-details.mjs:40`**: a real rule missing from A13; added there. It fails rather than
  warns because a beat with detail tags and no name has an Open chip with no page behind it.
- **`scripts/code-check.mjs:66`**: a tooling change outside this plan's steps, made after the
  implementation so the code check would read the smaller calls (m rows) too; without it every m row
  would have come back as unexplained.
